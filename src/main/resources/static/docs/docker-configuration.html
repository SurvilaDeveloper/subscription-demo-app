Docker y configuración de StreamBox Demo

Esta guía explica cómo configurar StreamBox Demo cuando se ejecuta con Docker y cómo debe comunicarse con Mock Payment Service.

StreamBox Demo representa una aplicación principal. Mock Payment Service representa la pasarela de pagos simulada. Para que el flujo funcione, ambos servicios deben poder llamarse entre sí.

En el flujo actual, StreamBox separa dos acciones: primero se crea la suscripción y la preapproval; después se paga una suscripción existente con una tarjeta ficticia. Esa separación no cambia la configuración de Docker, pero ayuda a entender mejor qué servicio llama a cuál.

Regla principal: el navegador usa localhost, pero un contenedor debe llamar a otro contenedor usando el nombre del servicio o del contenedor dentro de la red Docker.

Idea central

Navegador
  ↓
http://localhost:8080/
  ↓
StreamBox Demo container
  ↓ Suscribirme: crea preapproval
http://mock-payment-service:9090
  ↓ Pagar: genera payment
http://mock-payment-service:9090
  ↓
Mock Payment Service container
  ↓ envía webhook
http://subscription-demo-app:8080/api/webhooks/mock-payment

Hay dos tipos de URLs importantes:

URL Quién la usa Ejemplo
URL pública Tu navegador en Windows. http://localhost:8080
URL interna Docker Un contenedor llamando a otro contenedor. http://mock-payment-service:9090

Puertos

StreamBox Demo escucha internamente en el puerto: 

8080

Docker puede publicar ese puerto interno en otro puerto de la máquina host. 

ports:
  - "${DEMO_APP_HOST_PORT:-8080}:8080"

La parte izquierda es el puerto de tu máquina. La parte derecha es el puerto interno del contenedor. 

"8085:8080"

8085 → puerto en Windows / navegador
8080 → puerto dentro del contenedor

Ejemplo con puerto por defecto

docker compose up --build

Abrir:

http://localhost:8080/

Ejemplo con puerto personalizado

DEMO_APP_HOST_PORT=8085 docker compose up --build

Abrir:

http://localhost:8085/
Aunque StreamBox se publique en 8085, dentro de Docker sigue escuchando en 8080. Por eso Mock Payment Service debe enviar webhooks a http://subscription-demo-app:8080.

Variables principales

Variable Uso Valor típico
DEMO_APP_HOST_PORT Puerto publicado en la máquina host. 8080 o 8085
MOCK_PAYMENT_BASE_URL URL que StreamBox usa para llamar a Mock Payment Service. http://mock-payment-service:9090
MOCK_PAYMENT_WEBHOOK_SECRET Secret usado para validar webhooks recibidos. dev-secret
DEMO_APP_PUBLIC_BASE_URL URL pública de StreamBox para navegador o links visibles. http://localhost:8080
DEMO_APP_WEBHOOK_BASE_URL URL interna que Mock Payment Service usa para enviar webhooks a StreamBox. http://subscription-demo-app:8080
DEMO_APP_STORAGE_TYPE Tipo de persistencia del estado interno. file o memory
DEMO_APP_STORAGE_FILE_PATH Ruta del archivo de estado dentro del contenedor. /app/data/subscription-demo-state.bin

Red Docker compartida

Si StreamBox Demo y Mock Payment Service corren en contenedores separados, ambos deben estar en la misma red Docker.

Crear la red una sola vez: 

docker network create payment-demo-network

En el docker-compose.yml de StreamBox: 

networks:
  - payment-demo-network

networks:
  payment-demo-network:
    external: true

En el docker-compose.yml de Mock Payment Service también debe aparecer la misma red externa.

MOCK_PAYMENT_BASE_URL

Esta variable le dice a StreamBox dónde está Mock Payment Service.

Cuando StreamBox corre en Docker

Debe usar el nombre del servicio dentro de la red Docker: 

MOCK_PAYMENT_BASE_URL=http://mock-payment-service:9090

No debe usar: 

MOCK_PAYMENT_BASE_URL=http://localhost:9090

Porque dentro del contenedor de StreamBox, localhost significa el propio contenedor de StreamBox, no Mock Payment Service.

Cuando StreamBox corre en la máquina host

Si StreamBox se ejecuta directamente con Maven en Windows y Mock Payment Service está publicado en el puerto 9090, entonces sí puede usar: 

MOCK_PAYMENT_BASE_URL=http://localhost:9090

DEMO_APP_WEBHOOK_BASE_URL

Esta variable define la URL que StreamBox le entrega a Mock Payment Service como endpoint para recibir webhooks.

En Docker, Mock Payment Service debe poder llamar a StreamBox por nombre de contenedor: 

DEMO_APP_WEBHOOK_BASE_URL=http://subscription-demo-app:8080

Entonces StreamBox construye el webhook URL final así: 

http://subscription-demo-app:8080/api/webhooks/mock-payment

Por qué no usar localhost acá

Si Mock Payment Service corre en Docker y recibe este webhook URL: 

http://localhost:8080/api/webhooks/mock-payment

va a intentar llamar al puerto 8080 dentro de su propio contenedor. Eso no es StreamBox.

En cambio, debe usar: 

http://subscription-demo-app:8080/api/webhooks/mock-payment

DEMO_APP_PUBLIC_BASE_URL

Esta variable representa la URL pública de StreamBox para el navegador. 

DEMO_APP_PUBLIC_BASE_URL=http://localhost:8080

Si publicás StreamBox en otro puerto: 

DEMO_APP_HOST_PORT=8085

entonces conviene usar: 

DEMO_APP_PUBLIC_BASE_URL=http://localhost:8085

Esta URL es distinta de la URL interna de webhook.

Variable Valor con puerto 8085
DEMO_APP_PUBLIC_BASE_URL http://localhost:8085
DEMO_APP_WEBHOOK_BASE_URL http://subscription-demo-app:8080

Persistencia

StreamBox Demo puede guardar su estado interno en memoria o en archivo.

Modo Descripción
memory El estado se pierde al reiniciar.
file El estado se guarda en archivo y sobrevive a reinicios.

Configuración típica en Docker

DEMO_APP_STORAGE_TYPE=file
DEMO_APP_STORAGE_FILE_PATH=/app/data/subscription-demo-state.bin

Con volumen: 

volumes:
  - ./data:/app/data

El archivo queda persistido en: 

./data/subscription-demo-state.bin
La carpeta data/ no debería commitearse. Es estado local de desarrollo.

Casos frecuentes

Caso 1: ambos servicios con puertos por defecto

Mock Payment Service:
http://localhost:9090/studio/

StreamBox Demo:
http://localhost:8080/

Variables típicas de StreamBox:

MOCK_PAYMENT_BASE_URL=http://mock-payment-service:9090
MOCK_PAYMENT_WEBHOOK_SECRET=dev-secret
DEMO_APP_PUBLIC_BASE_URL=http://localhost:8080
DEMO_APP_WEBHOOK_BASE_URL=http://subscription-demo-app:8080

Caso 2: StreamBox publicado en 8085

DEMO_APP_HOST_PORT=8085 docker compose up --build

Abrir:

http://localhost:8085/

Variables recomendadas:

DEMO_APP_PUBLIC_BASE_URL=http://localhost:8085
DEMO_APP_WEBHOOK_BASE_URL=http://subscription-demo-app:8080
MOCK_PAYMENT_BASE_URL=http://mock-payment-service:9090

Caso 3: Mock Payment Service publicado en 9095

Desde el navegador, Mock Payment Studio se abre en: 

http://localhost:9095/studio/

Pero StreamBox en Docker debe seguir usando: 

MOCK_PAYMENT_BASE_URL=http://mock-payment-service:9090

Caso 4: StreamBox corre en host y Mock en Docker

Si StreamBox corre con Maven directamente en la máquina host: 

MOCK_PAYMENT_BASE_URL=http://localhost:9090

Pero Mock Payment Service, para enviar webhooks hacia la app en host, debería recibir: 

DEMO_APP_WEBHOOK_BASE_URL=http://host.docker.internal:8080

El webhook final sería: 

http://host.docker.internal:8080/api/webhooks/mock-payment

Errores comunes

StreamBox no puede llamar a Mock Payment Service

Revisar que StreamBox no esté usando:

MOCK_PAYMENT_BASE_URL=http://localhost:9090

Si corre en Docker, debe usar:

MOCK_PAYMENT_BASE_URL=http://mock-payment-service:9090

Mock Payment Service no puede entregar webhooks

Revisar que StreamBox no haya enviado como notification URL:

http://localhost:8080/api/webhooks/mock-payment

Si ambos corren en Docker, debería ser:

http://subscription-demo-app:8080/api/webhooks/mock-payment

Firma inválida

Revisar que ambos servicios usen el mismo secret: 

MOCK_PAYMENT_WEBHOOK_SECRET=dev-secret

El estado viejo aparece después de reiniciar

Si usás storage file, StreamBox conserva estado en: 

./data/

Para limpiar: 

docker compose down
rm -rf data
docker compose up --build

O usar el botón: 

Resetear demo

Checklist de configuración

  1. Docker Desktop está corriendo.
  2. Existe la red payment-demo-network.
  3. Mock Payment Service está levantado.
  4. StreamBox Demo está levantado.
  5. Ambos contenedores están en la misma red.
  6. StreamBox usa MOCK_PAYMENT_BASE_URL=http://mock-payment-service:9090.
  7. StreamBox usa DEMO_APP_WEBHOOK_BASE_URL=http://subscription-demo-app:8080.
  8. El secret coincide en ambos servicios.
  9. El navegador abre StreamBox con el puerto publicado correcto.
  10. El navegador abre Mock Payment Studio con el puerto publicado correcto.
  11. Se puede usar Suscribirme para crear la preapproval.
  12. Se puede usar Pagar para generar el pago y recibir el webhook.
Si la integración falla, casi siempre el problema está en una de estas tres cosas: uso incorrecto de localhost, contenedores en redes distintas o secrets diferentes.
