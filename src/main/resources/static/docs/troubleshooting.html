Troubleshooting de StreamBox Demo

Esta guía ayuda a diagnosticar problemas comunes al usar StreamBox Demo junto con Mock Payment Service.

La mayoría de los errores aparecen por configuración de Docker, uso incorrecto de localhost, puertos ocupados, servicios en redes distintas, secrets diferentes o estado persistido de pruebas anteriores.

Regla práctica: primero revisar conectividad y configuración. Después revisar webhooks, firma y procesamiento interno.

Diagnóstico rápido

Antes de revisar casos específicos, ejecutar: 

docker ps
docker network ls

Verificar que estén corriendo los dos contenedores: 

mock-payment-service
subscription-demo-app

Verificar que Mock Payment Service responda: 

curl http://localhost:9090/health

Respuesta esperada: 

OK

Verificar que StreamBox abra en el navegador: 

http://localhost:8080/

Docker no responde

Si aparece un error parecido a: 

Docker Desktop is unable to start

significa que Docker Desktop o el daemon de Docker no están corriendo correctamente.

Soluciones

  1. Abrir Docker Desktop manualmente.
  2. Esperar a que termine de iniciar.
  3. Ejecutar docker ps.
  4. Si sigue fallando, cerrar Docker Desktop.
  5. Ejecutar wsl --shutdown desde PowerShell.
  6. Abrir Docker Desktop nuevamente.
wsl --shutdown
En Windows, Docker Desktop depende de WSL 2. Si WSL queda trabado, Docker puede dejar de responder aunque los archivos del proyecto estén bien.

StreamBox no abre en el navegador

URL esperada con configuración por defecto: 

http://localhost:8080/

Revisar contenedor

docker ps

Buscar algo parecido a: 

subscription-demo-app   0.0.0.0:8080->8080/tcp

Ver logs

docker logs subscription-demo-app

Posibles causas

  • Docker Desktop no está corriendo.
  • El contenedor no levantó.
  • El puerto publicado no es 8080.
  • El puerto está ocupado por otra aplicación.
  • El navegador está abriendo una URL vieja.

Si usaste otro puerto

Si levantaste StreamBox con: 

DEMO_APP_HOST_PORT=8085 docker compose up --build

entonces tenés que abrir: 

http://localhost:8085/

StreamBox no conecta con Mock Payment Service

Síntoma típico: al presionar Suscribirme, StreamBox falla al crear la preapproval, o al presionar Pagar, falla al simular el pago.

Revisar que Mock esté levantado

curl http://localhost:9090/health

Revisar configuración en la UI

En StreamBox, mirar la sección: 

Configuración de integración

Si StreamBox corre en Docker, el valor correcto es: 

MOCK_PAYMENT_BASE_URL=http://mock-payment-service:9090

Este valor sería incorrecto dentro de Docker: 

MOCK_PAYMENT_BASE_URL=http://localhost:9090

Porque desde el contenedor de StreamBox, localhost apunta al propio contenedor de StreamBox, no al contenedor de Mock Payment Service.

Puertos ocupados

StreamBox: puerto 8080 ocupado

Usar otro puerto publicado: 

DEMO_APP_HOST_PORT=8085 \
DEMO_APP_PUBLIC_BASE_URL=http://localhost:8085 \
docker compose up --build

Abrir: 

http://localhost:8085/

Mock Payment Service: puerto 9090 ocupado

Desde el proyecto de Mock Payment Service: 

MOCK_PAYMENT_HOST_PORT=9095 \
MOCK_PAYMENT_BASE_URL=http://localhost:9095 \
docker compose up --build

Abrir Mock Payment Studio en: 

http://localhost:9095/studio/
Si ambos servicios corren en Docker, cambiar el puerto publicado en host no cambia la comunicación interna. StreamBox debe seguir llamando a http://mock-payment-service:9090.

Problemas con la red Docker

Si los proyectos corren en contenedores separados, ambos deben estar conectados a: 

payment-demo-network

Crear red

docker network create payment-demo-network

Inspeccionar red

docker network inspect payment-demo-network

En la salida deberían aparecer: 

mock-payment-service
subscription-demo-app

Error típico

StreamBox y Mock están levantados, pero no se ven entre sí.

Causas posibles:

  • Uno de los proyectos no está usando la red externa.
  • La red externa no existe.
  • Un contenedor fue levantado antes de crear la red.
  • El nombre del contenedor o servicio no coincide con la URL configurada.

El webhook no llega a StreamBox

Síntoma típico:

  • Mock Payment Studio muestra delivered=false.
  • StreamBox no muestra nada en Webhooks recibidos por StreamBox.
  • La suscripción no se actualiza después del pago.

URL correcta con ambos servicios en Docker

http://subscription-demo-app:8080/api/webhooks/mock-payment

URL incorrecta con ambos servicios en Docker

http://localhost:8080/api/webhooks/mock-payment

Esa URL es incorrecta porque, desde el contenedor de Mock Payment Service, localhost apunta al propio mock.

Qué revisar

  1. En StreamBox, revisar DEMO_APP_WEBHOOK_BASE_URL.
  2. Debe ser http://subscription-demo-app:8080 si ambos corren en Docker.
  3. En Mock Payment Studio, revisar el webhook saliente.
  4. Ver si aparece delivered=true o delivered=false.
  5. En StreamBox, revisar la tabla Webhooks recibidos por StreamBox.

Firma inválida

Síntoma típico:

  • StreamBox recibe el webhook.
  • Pero aparece como firma inválida o procesamiento fallido.
  • En la tabla de webhooks recibidos aparece un error.

Revisar secret

Mock Payment Service firma webhooks con: 

MOCK_PAYMENT_WEBHOOK_SECRET

StreamBox valida webhooks con el mismo valor: 

MOCK_PAYMENT_WEBHOOK_SECRET=dev-secret

Si los valores no coinciden, StreamBox rechaza el webhook.

Valor recomendado para la demo

MOCK_PAYMENT_WEBHOOK_SECRET=dev-secret
En producción, el secret no debería ser dev-secret. Debería ser un valor seguro, privado y configurado fuera del repositorio.

Estado viejo o datos inconsistentes

StreamBox y Mock Payment Service tienen estados separados.

Aplicación Qué guarda
StreamBox Demo Suscripciones internas, pagos internos, webhooks recibidos y eventos internos.
Mock Payment Service Preapprovals, payments, webhooks salientes y receptor interno.

Resetear solo StreamBox

Usar el botón: 

Resetear demo

Resetear solo Mock Payment Service

Desde Mock Payment Studio: 

Resetear estado

O por curl: 

curl -X DELETE http://localhost:9090/mock/state

Borrar datos persistidos de StreamBox

docker compose down
rm -rf data
docker compose up --build

En Windows también se puede borrar manualmente la carpeta: 

./data/

El pago no aparece en StreamBox

Si el pago aparece en Mock Payment Service pero no aparece en StreamBox, revisar:

Recordá que el flujo está separado: primero hay que crear la suscripción con Suscribirme y después generar el pago inicial con Pagar. Si solo se creó la suscripción, todavía no debería existir un pago interno.
  1. Si el webhook fue enviado.
  2. Si Mock Payment Studio muestra delivered=true.
  3. Si StreamBox recibió el webhook.
  4. Si la firma fue válida.
  5. Si el webhook fue procesado.
  6. Si StreamBox pudo consultar GET /payment/{id}.

En la UI de StreamBox, revisar: 

Webhooks recibidos por StreamBox
Pagos internos
Eventos internos

La suscripción no cambia de estado

StreamBox actualiza su estado interno cuando:

  • Recibe una respuesta directa al pagar.
  • Procesa un webhook de pago.
  • Procesa un webhook de preapproval.
  • Consulta el estado actualizado al proveedor.

Qué revisar

  1. Que la suscripción interna tenga providerSubscriptionId.
  2. Que el pago externo tenga preapprovalId.
  3. Que StreamBox encuentre la suscripción por provider ID.
  4. Que el estado externo sea mapeable a estado interno.
  5. Que no haya error en Eventos internos.

Estados esperados

Proveedor StreamBox
pending PENDING
authorized ACTIVE
payment_failed PAYMENT_FAILED
paused PAUSED
cancelled CANCELLED

Checklist final

  1. Docker Desktop está corriendo.
  2. Mock Payment Service está levantado.
  3. StreamBox Demo está levantado.
  4. La red payment-demo-network existe.
  5. Ambos contenedores están en la red compartida.
  6. StreamBox abre desde el navegador.
  7. Mock Payment Studio abre desde el navegador.
  8. MOCK_PAYMENT_BASE_URL es correcto.
  9. DEMO_APP_WEBHOOK_BASE_URL es correcto.
  10. El secret coincide en ambos servicios.
  11. Se puede crear una suscripción desde StreamBox con Suscribirme.
  12. Se puede pagar una suscripción existente con Pagar.
  13. Mock Payment Service genera el pago.
  14. Mock Payment Studio muestra el webhook saliente.
  15. StreamBox muestra el webhook recibido.
  16. La firma aparece válida.
  17. El webhook aparece procesado.
  18. La suscripción interna cambia de estado.
  19. El pago interno aparece registrado.
Si el problema sigue, el lugar más útil para mirar suele ser la combinación de: Configuración de integración, Webhooks recibidos por StreamBox, Eventos internos y Webhooks salientes en Mock Payment Studio.
