Guía rápida de uso de StreamBox Demo

Esta guía muestra el recorrido mínimo para probar StreamBox Demo junto con Mock Payment Service.

StreamBox Demo representa una aplicación principal real. Mock Payment Service representa la pasarela de pagos simulada. El objetivo es ver el flujo completo desde el punto de vista de la aplicación que vende una suscripción.

StreamBox no es la pasarela de pagos. StreamBox es la aplicación que necesita cobrar. Mock Payment Service es el proveedor simulado que crea suscripciones, pagos y webhooks.

Requisitos

Para probar el flujo completo se necesitan dos aplicaciones:

Aplicación Rol Puerto típico
Mock Payment Service Pasarela de pagos simulada. 9090
StreamBox Demo Aplicación principal que vende planes. 8080

También se necesita Docker Desktop corriendo si se usan los contenedores.

1. Crear la red Docker compartida

Si Mock Payment Service y StreamBox Demo corren en contenedores separados, ambos deben compartir una red Docker.

Crear la red una sola vez: 

docker network create payment-demo-network

Si la red ya existe, Docker puede mostrar un mensaje indicando que ya fue creada. En ese caso, no hace falta crearla de nuevo.

2. Levantar Mock Payment Service

Desde la carpeta del proyecto mock-payment-service: 

docker compose up --build

Con la configuración por defecto, Mock Payment Studio queda disponible en: 

http://localhost:9090/studio/

Para verificar que el mock está levantado: 

curl http://localhost:9090/health

Respuesta esperada: 

OK

Si el puerto 9090 está ocupado

Se puede levantar Mock Payment Service en otro puerto publicado: 

MOCK_PAYMENT_HOST_PORT=9095 \
MOCK_PAYMENT_BASE_URL=http://localhost:9095 \
docker compose up --build

En ese caso, desde el navegador se abre: 

http://localhost:9095/studio/
Aunque Mock Payment Service se publique en otro puerto de la máquina host, otros contenedores deben seguir llamándolo con http://mock-payment-service:9090.

3. Levantar StreamBox Demo

Desde la carpeta del proyecto subscription-demo-app: 

docker compose up --build

Con el puerto por defecto, StreamBox queda disponible en: 

http://localhost:8080/

Configuración esperada en Docker

Cuando StreamBox corre en Docker, debe llamar a Mock Payment Service usando el nombre del servicio dentro de la red Docker: 

MOCK_PAYMENT_BASE_URL=http://mock-payment-service:9090
MOCK_PAYMENT_WEBHOOK_SECRET=dev-secret
DEMO_APP_PUBLIC_BASE_URL=http://localhost:8080
DEMO_APP_WEBHOOK_BASE_URL=http://subscription-demo-app:8080

La idea es: 

StreamBox container → Mock Payment container
http://mock-payment-service:9090

Mock Payment container → StreamBox container
http://subscription-demo-app:8080/api/webhooks/mock-payment

Levantar StreamBox en otro puerto

Si el puerto 8080 está ocupado, se puede publicar StreamBox en otro puerto: 

DEMO_APP_HOST_PORT=8085 docker compose up --build

En ese caso, desde el navegador se abre: 

http://localhost:8085/

Pero internamente el contenedor sigue escuchando en 8080. Por eso Mock Payment Service debe seguir enviando webhooks a: 

http://subscription-demo-app:8080/api/webhooks/mock-payment

4. Abrir la UI de StreamBox

Abrir en el navegador: 

http://localhost:8080/

Si se usó otro puerto: 

http://localhost:8085/

En la pantalla principal deberías ver:

  • Estado de la aplicación principal.
  • Configuración de integración.
  • Sección de suscripción y pago.
  • Acciones sobre una suscripción.
  • Planes disponibles.
  • Suscripciones internas.
  • Pagos internos.
  • Webhooks recibidos.
  • Eventos internos.

5. Revisar configuración de integración

Antes de probar una suscripción o un pago, revisar la sección: 

Configuración de integración

Ahí StreamBox muestra las URLs reales que está usando para comunicarse con Mock Payment Service.

Campo Qué debería indicar
Mock Payment Base URL http://mock-payment-service:9090 si StreamBox corre en Docker.
Webhook Base URL http://subscription-demo-app:8080 si Mock debe llamar a StreamBox dentro de Docker.
Webhook Secret Debe coincidir con el secret configurado en Mock Payment Service.

6. Suscribirse

En la sección: 

Suscripción y pago → Suscribirme

Elegir un plan, dejar el email de prueba o ingresar otro, y presionar: 

Suscribirme

En este paso todavía no se genera el pago. StreamBox crea una suscripción interna y registra una preapproval en Mock Payment Service.

Flujo esperado: 

StreamBox crea suscripción interna PENDING
  ↓
StreamBox llama a Mock Payment Service
  ↓
Mock crea preapproval
  ↓
StreamBox guarda providerSubscriptionId
  ↓
La suscripción queda lista para pagar

Qué revisar después de suscribirse

Sección Resultado esperado
Suscripciones internas Debe aparecer una nueva suscripción interna.
Provider subscription ID Debe tener el ID externo generado por Mock Payment Service.
Estado Normalmente queda PENDING hasta que se pague.
Pagos internos Todavía no debería aparecer un pago por esta suscripción.
Separar la suscripción del pago ayuda a entender mejor el flujo real: primero se crea la intención o suscripción, después se intenta cobrar.

7. Pagar

Después de crear una suscripción, usar: 

Suscripción y pago → Pagar

Elegir una suscripción existente, seleccionar una tarjeta ficticia y presionar: 

Pagar

Pago aprobado

4111111111111111

Flujo esperado: 

StreamBox toma una suscripción existente
  ↓
StreamBox simula pago con tarjeta ficticia
  ↓
Mock crea payment
  ↓
Mock envía webhook a StreamBox
  ↓
StreamBox valida firma
  ↓
StreamBox consulta GET /payment/{id}
  ↓
StreamBox consulta GET /preapproval/{id}
  ↓
StreamBox registra pago interno
  ↓
StreamBox actualiza estado interno

Tarjetas útiles

Tarjeta Resultado esperado
4111111111111111 Pago aprobado.
4000000000000002 Sin fondos.
4000000000009995 Número inválido.
4000000000000069 Tarjeta vencida.
4000000000000341 Pago pendiente.
4000000000000259 Error genérico.

8. Verificar el resultado en StreamBox

Después de pagar con tarjeta aprobada, revisar:

Sección Resultado esperado
Suscripciones internas Debe aparecer una suscripción con estado interno activo o equivalente.
Pagos internos Debe aparecer un pago asociado a la suscripción.
Webhooks recibidos por StreamBox Debe aparecer el webhook recibido desde Mock Payment Service.
Eventos internos Debe quedar registrado el flujo educativo de la operación.

Si el pago fue rechazado, StreamBox debería registrar el pago fallido y dejar la suscripción en un estado interno acorde.

Si el pago quedó pendiente, StreamBox debería registrar un pago en proceso y conservar un estado interno que no habilite la suscripción como si ya estuviera aprobada.

9. Revisar webhooks en Mock Payment Studio

Abrir Mock Payment Studio: 

http://localhost:9090/studio/

Revisar la tabla: 

Webhooks salientes

Si el webhook fue entregado correctamente a StreamBox, deberías ver: 

delivered=true

Puede aparecer: 

received internally=false

Eso es correcto si el webhook fue enviado a StreamBox Demo, porque no fue enviado al receptor interno de Mock Payment Service.

En este caso, StreamBox es la aplicación externa receptora. Por eso el webhook se ve como entregado en Mock Payment Studio y como recibido en StreamBox Demo.

10. Probar acciones posteriores

Una vez creada una suscripción, se pueden probar acciones posteriores:

  • Simular cobro recurrente.
  • Cambiar plan.
  • Cancelar suscripción.

Simular cobro recurrente

Usar la sección: 

Acciones sobre una suscripción → Simular cobro recurrente

Esto genera un nuevo pago sobre una suscripción existente.

Cambiar plan

Usar: 

Acciones sobre una suscripción → Cambiar plan

Esto actualiza el plan en StreamBox y en el proveedor simulado.

Cancelar suscripción

Usar: 

Acciones sobre una suscripción → Cancelar suscripción

Esto cancela la suscripción y registra el evento correspondiente.

11. Resetear demo

Para volver a empezar, usar: 

Resetear demo

Esto limpia el estado interno de StreamBox Demo.

Si querés limpiar también Mock Payment Service, abrir Mock Payment Studio y usar: 

Resetear estado

O por curl: 

curl -X DELETE http://localhost:9090/mock/state
StreamBox y Mock Payment Service tienen estados separados. Resetear StreamBox no necesariamente borra el estado del mock, y resetear el mock no necesariamente borra el estado interno de StreamBox.

Resumen del flujo completo

1. Crear red Docker:
   docker network create payment-demo-network

2. Levantar Mock Payment Service:
   docker compose up --build

3. Levantar StreamBox Demo:
   docker compose up --build

4. Abrir StreamBox:
   http://localhost:8080/

5. Suscribirse:
   elegir plan
   ingresar email
   presionar Suscribirme

6. Pagar:
   elegir suscripción
   elegir tarjeta 4111111111111111
   presionar Pagar

7. Verificar en StreamBox:
   suscripción interna
   pago interno
   webhook recibido
   evento interno

8. Verificar en Mock Payment Studio:
   webhook saliente delivered=true
Si este flujo funciona, la integración básica entre StreamBox Demo y Mock Payment Service está correctamente configurada.
