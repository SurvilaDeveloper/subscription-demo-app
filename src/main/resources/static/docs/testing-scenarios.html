Escenarios de prueba de StreamBox Demo

Esta guía enumera escenarios prácticos para probar StreamBox Demo como aplicación principal integrada con Mock Payment Service.

La diferencia con probar solo Mock Payment Service es que acá se revisa qué pasa dentro de StreamBox: suscripciones internas, pagos internos, webhooks recibidos y eventos internos.

Antes de probar escenarios importantes, conviene resetear StreamBox y Mock Payment Service para empezar desde un estado limpio.

Preparación

1. Levantar Mock Payment Service

Desde la carpeta de Mock Payment Service: 

docker compose up --build

Abrir: 

http://localhost:9090/studio/

2. Levantar StreamBox Demo

Desde la carpeta de StreamBox Demo: 

docker compose up --build

Abrir: 

http://localhost:8080/

3. Revisar configuración

En StreamBox, revisar la sección: 

Configuración de integración

Valores esperados si ambos servicios corren en Docker: 

MOCK_PAYMENT_BASE_URL=http://mock-payment-service:9090
DEMO_APP_WEBHOOK_BASE_URL=http://subscription-demo-app:8080
MOCK_PAYMENT_WEBHOOK_SECRET=dev-secret

4. Resetear estados

En StreamBox: 

Resetear demo

En Mock Payment Studio: 

Resetear estado

Escenario 1: pago aprobado

Este es el escenario base. Sirve para comprobar que la integración completa funciona: StreamBox crea la suscripción, Mock Payment Service aprueba el pago, se envía webhook y StreamBox actualiza su estado interno.

Campo Valor
Tarjeta 4111111111111111
Pago esperado en Mock approved
Pago interno esperado APPROVED
Suscripción interna esperada ACTIVE
Webhook esperado payment.created

Pasos

  1. En StreamBox, ir a Suscribirse a StreamBox.
  2. Elegir cualquier plan.
  3. Dejar el email de prueba o ingresar otro email.
  4. Elegir la tarjeta 4111111111111111.
  5. Presionar Suscribirme y pagar.

Qué revisar en StreamBox

  • En Suscripciones internas, la suscripción debería quedar activa.
  • En Pagos internos, debería aparecer un pago aprobado.
  • En Webhooks recibidos por StreamBox, debería aparecer un webhook con firma válida.
  • En Eventos internos, debería verse el flujo completo.

Qué revisar en Mock Payment Studio

  • En Preapprovals, debería existir la suscripción externa.
  • En Payments, debería existir el pago aprobado.
  • En Webhooks salientes, debería aparecer delivered=true.
Si Mock Payment Studio muestra delivered=true y StreamBox muestra el webhook recibido, el flujo de integración está funcionando correctamente.

Escenario 2: pago rechazado

Este escenario sirve para comprobar que StreamBox registra un pago fallido y no activa la suscripción como si el pago hubiera sido exitoso.

Tarjeta Resultado Pago interno esperado Suscripción esperada
4000000000000002 Sin fondos REJECTED PAYMENT_FAILED
4000000000009995 Número inválido REJECTED PAYMENT_FAILED
4000000000000069 Tarjeta vencida REJECTED PAYMENT_FAILED
4000000000000259 Error genérico REJECTED PAYMENT_FAILED

Pasos

  1. Resetear StreamBox y Mock Payment Service.
  2. Crear una suscripción desde StreamBox.
  3. Elegir una tarjeta de rechazo, por ejemplo 4000000000000002.
  4. Presionar Suscribirme y pagar.

Qué revisar

  • La suscripción interna no debería quedar ACTIVE.
  • El pago interno debería quedar REJECTED.
  • El webhook debería ser recibido y procesado.
  • Los eventos internos deberían explicar el resultado.

Escenario 3: pago pendiente

Este escenario sirve para probar pagos que no se aprueban ni se rechazan inmediatamente.

Tarjeta Pago en Mock Pago interno Suscripción interna
4000000000000341 in_process IN_PROCESS PENDING

Pasos

  1. Resetear estados.
  2. Crear una suscripción desde StreamBox.
  3. Elegir la tarjeta 4000000000000341.
  4. Presionar Suscribirme y pagar.

Qué revisar

  • El pago interno debería quedar en proceso.
  • La suscripción no debería habilitar acceso completo como si estuviera activa.
  • El webhook debería quedar registrado.

Escenario 4: cobro recurrente aprobado

Este escenario sirve para probar renovaciones o cobros posteriores sobre una suscripción existente.

Preparación

  1. Crear una suscripción con tarjeta aprobada.
  2. Verificar que la suscripción quede activa.

Pasos

  1. Ir a Acciones sobre una suscripción.
  2. En Simular cobro recurrente, elegir la suscripción.
  3. Elegir la tarjeta 4111111111111111.
  4. Presionar Simular cobro.

Resultado esperado

  • Se crea un nuevo pago interno.
  • El nuevo pago queda APPROVED.
  • La suscripción se mantiene activa.
  • Se recibe y procesa un nuevo webhook.

Escenario 5: cobro recurrente fallido

Este escenario sirve para probar una renovación fallida.

Preparación

  1. Crear una suscripción con pago aprobado.
  2. Verificar que la suscripción esté activa.

Pasos

  1. Ir a Acciones sobre una suscripción.
  2. En Simular cobro recurrente, elegir la suscripción.
  3. Elegir 4000000000000002.
  4. Presionar Simular cobro.

Resultado esperado

  • Se crea un pago interno rechazado.
  • La suscripción puede pasar a PAYMENT_FAILED.
  • StreamBox registra el webhook recibido.
  • Los eventos internos muestran el cambio.
En una aplicación real, este escenario suele disparar avisos al usuario, reintentos, suspensión del servicio o reglas de gracia según el negocio.

Escenario 6: cambio de plan

Este escenario prueba que StreamBox pueda cambiar el plan interno y sincronizar ese cambio con Mock Payment Service.

Preparación

  1. Crear una suscripción activa.
  2. Verificar el plan actual en Suscripciones internas.

Pasos

  1. Ir a Acciones sobre una suscripción.
  2. En Cambiar plan, elegir la suscripción.
  3. Elegir un nuevo plan.
  4. Presionar Cambiar plan.

Resultado esperado

  • La suscripción conserva el mismo ID interno.
  • Cambia el plan interno.
  • Cambia el monto interno.
  • Se consulta el estado actualizado al proveedor.
  • Se registra un evento interno de cambio de plan.

Escenario 7: cancelación de suscripción

Este escenario prueba la cancelación desde la aplicación principal.

Preparación

  1. Crear una suscripción.
  2. Preferentemente usar una suscripción activa.

Pasos

  1. Ir a Acciones sobre una suscripción.
  2. En Cancelar suscripción, elegir la suscripción.
  3. Presionar Cancelar suscripción.

Resultado esperado

  • StreamBox llama al proveedor simulado para cancelar.
  • StreamBox consulta la preapproval actualizada.
  • La suscripción interna queda CANCELLED.
  • Se registra un evento interno de cancelación.
  • Mock Payment Service puede generar un webhook de cancelación.

Escenario 8: revisar webhooks cruzados

Este escenario sirve para entender qué se ve en cada aplicación.

En Mock Payment Studio

Revisar: 

Webhooks salientes

Cuando el destino es StreamBox, puede verse: 

delivered=true
received internally=false

Eso es correcto. Significa que el webhook fue entregado a StreamBox, no al receptor interno de Mock Payment Service.

En StreamBox Demo

Revisar: 

Webhooks recibidos por StreamBox

Ahí debería aparecer:

  • Request ID.
  • Evento.
  • Data ID.
  • Firma válida.
  • Procesado.
  • Error si ocurrió.

Escenario 9: resetear estados

StreamBox y Mock Payment Service guardan estados separados.

Reset Qué borra
Resetear demo en StreamBox Suscripciones internas, pagos internos, webhooks recibidos y eventos internos de StreamBox.
Resetear estado en Mock Payment Studio Preapprovals, payments, webhooks salientes y estado interno del mock.

Prueba recomendada

  1. Crear una suscripción y pagarla.
  2. Ver datos en StreamBox y en Mock Payment Studio.
  3. Resetear solo StreamBox.
  4. Ver que Mock Payment Service conserva su estado.
  5. Resetear solo Mock Payment Service.
  6. Ver que StreamBox conserva su estado hasta que también sea reseteado.
Esta separación es intencional. StreamBox representa la aplicación principal y Mock Payment Service representa el proveedor. En una integración real, cada sistema conserva su propio estado.

Checklist antes de considerar la integración correcta

  1. Se puede abrir StreamBox desde el navegador.
  2. Se puede abrir Mock Payment Studio desde el navegador.
  3. StreamBox muestra configuración correcta de integración.
  4. Se puede crear una suscripción con pago aprobado.
  5. La suscripción interna queda activa.
  6. El pago interno queda aprobado.
  7. Mock Payment Studio muestra webhook entregado.
  8. StreamBox muestra webhook recibido.
  9. La firma del webhook aparece válida.
  10. El webhook aparece procesado.
  11. Se puede probar pago rechazado.
  12. Se puede probar pago pendiente.
  13. Se puede probar cobro recurrente.
  14. Se puede cambiar de plan.
  15. Se puede cancelar una suscripción.
  16. Los eventos internos ayudan a entender qué ocurrió.
Una integración de pagos no está bien probada solo porque el pago aprobado funciona. También conviene probar rechazos, pendientes, renovaciones, cancelaciones, webhooks y resets.
